# Learning and evaluation contracts

`train_dataset(data_dir, audit_dir, output_dir, config, synthetic=False)` requires a fresh nonexistent or empty output directory, a feasible audit, matching synthetic provenance, the audit's target/quality/baseline/seed settings, and explicit operating targets. A nonempty output is rejected before reading the audit or modifying any file, so a failed new run cannot leave an older frozen model looking like its output. Use a new directory for each development release. The command reads ECG and rhythm labels only for train, calibration and validation patients. It verifies the complete dataset byte fingerprint against the audit before fitting. This integrity check reads bytes; test waveform features and labels are not used for model or operating-point selection. Audit-excluded duplicate/overlap/unannotated records never enter fitting or evaluation.

Ten comparisons are developed: clinical/core-ECG logistic; clinical/core-ECG/combined/personal XGBoost; enriched-ECG logistic; enriched combined/personal elastic net; and enriched personal XGBoost. The enriched ECG schema adds 17 explicitly allowlisted RR-dynamics features to the six core fields. Personal variants use deviations from prior baselines; enriched personal variants also use prior-only standardized deviations. Every numeric field gets a missingness indicator, including fields first missing after training. Identifiers, paths, filenames, labels and timestamps are excluded.

Two regularization settings per family are compared in up to three audited-group folds entirely within training. Median imputation and weighted logistic/elastic-net scaling fit only each fold's fitting rows. XGBoost uses ten-round early stopping on the held-out training groups, with a maximum of 80 trees. The median best tree count for the chosen depth/regularization is fixed before fitting all training groups. Calibration, validation and test cannot select that count. Fold group IDs, original patient counts, class counts, tree counts, convergence warnings and pooled out-of-fold coverage are archived. A usable candidate must converge and assess both classes in pooled OOF windows; negative-only holdout groups can contribute when pooled coverage includes positives. Group-macro log loss selects hyperparameters. Expected fit/calibration failures remain visible rather than blocking successful baselines; unexpected exceptions abort.

Default `training.sample_weighting=patient_class` gives each audited independent group equal total relative mass and equally weights its observed class cells. Within a fitting fold, a row gets `1/(number_of_observed_classes_in_group * windows_in_group_class)`, normalized to mean one. Audited aliases share one mass. Global class masses need not be 50/50. `patient_only` and legacy `window_class` are explicit controls. XGBoost early-stopping evaluation uses group-balanced `patient_only` weights; final weights are recomputed on training only. Mean-one normalization does not guarantee prediction invariance to duplicating a complete dataset because regularization depends on total loss mass.

A separate unweighted sigmoid calibrator fits calibration patients at natural monitoring prevalence. Its scalar score standardization uses calibration patients only; default `training.calibration_c=1` regularizes its logistic slope. Reports expose original score slope/intercept, convergence, prevalence, independent groups, score range, and calibration-fit diagnostics. Separate validation reports compare raw and calibrated probability metrics. Calibration-fit scores are not independent performance estimates.

Validation uses whole chronological records and the runtime's `advance_alert` policy. Nineteen thresholds from 0.05 to 0.95 retain the configured release-to-issue threshold ratio. Only thresholds meeting the supplied false-warning budget and minimum event sensitivity qualify. Among passing models, higher event sensitivity wins, then fewer false warnings; explicit family priority (logistic, elastic net, XGBoost), then fewer features, resolves exact operating ties; stable candidate order breaks any remaining tie. If none qualifies, training writes a failure report and creates no frozen model. A selected logistic baseline is a feasibility finding rather than evidence of XGBoost superiority. Operating targets supplied to the synthetic smoke command are software-check assumptions, not clinically approved targets.

The release contains `model.joblib`, `manifest.json`, `config.json`, `feature_schema.json`, `splits.json`, `training_report.json`, `model_card.md`, and each successfully fitted independently calibrated comparison package (up to ten) under `comparisons/`. The manifest freezes feature extraction version, training settings, audited patient-group links, fit failures, dataset fingerprint, record inclusion, seed, dependency versions and provenance. Legacy feature packages must be re-audited and retrained before use with the current extractor. `Predictor.load(path)` accepts trusted local joblib artifacts only. It checks the model checksum and verifies the ordered feature schema and configuration against the embedded contract; version strings include a content hash. `predict(features)` returns calibrated `risk`, top raw-score `evidence` contributions and textual `uncertainty`; contributions do not attribute calibrated probabilities or imply causation.

`evaluate_artifact(data_dir, audit_dir, artifact_dir, output_dir)` verifies the frozen dataset fingerprint and patient split, then opens only final-test records. It evaluates the selected model and all frozen comparisons on identical test patients and chronological feature rows, without selecting new parameters. `evaluation.json` and `predictions.jsonl` are separate from development results. Re-running evaluation is reproducible; its output must not be used to retune the frozen package.

`evaluate_stream(rows, events, config, bootstrap_samples=300)` accepts rows with `patient_id`, `record_id`, `timestamp`, `duration_seconds`, `accepted`, `risk`, `label`, `reason` and `label_reason`. Events contain `patient_id`, `record_id` and `onset`. Each record restarts its runtime alert state and baseline; all records of a patient and its audited linked IDs remain together for the bootstrap. Rows cover every cadence, including history and baseline warmup, quality rejection, current AF, uncertain annotation, washout and truncated follow-up. Baselines update from prior quality-accepted full-history windows before each subsequent prediction.

`match_warnings(warnings, onsets, gap, horizon)` sorts warning times and greedily matches the earliest eligible unmatched event, inclusive of both gap and horizon endpoints. Each warning and event participates at most once. The evaluator first removes every warning issued when `label` is unavailable (history, washout, unknown annotation and other exclusions), classifies it as **unassessable**, and reports its exclusion reason. Excluded warnings cannot match an event even when their timing falls inside the target interval; all still contribute to warning burden. Every annotation-eligible new onset stays in sensitivity, even if its valid warning opportunities were unavailable; audit quality exclusions cannot conceal those misses. Unmatched warnings issued in adequately labeled forecasting periods count as false.

Total monitored time and forecast coverage include all recording time, including unavailable forecasts. The canonical false-warning rate and policy budget use adequately labeled forecast-eligible hours, including quality-rejected windows, so unknown or excluded time cannot dilute the rate. `false_warnings_per_all_recording_hour` separately exposes the total-recording-time rate. Rejection reasons, annotation exclusions, missed events during complete abstention, total warning duration, cooldown-suppressed updates, lead times and assessable warning precision are explicit. Probability metrics use naturally occurring adequately labeled available windows: PR-AUC, Brier score, log loss, AUROC and ten-bin calibration/ECE. Probability reports add positive prevalence, a descriptive observed-prevalence AP/Brier reference and mean Brier across original patient IDs. Per-patient counts and lead-time quartiles expose pooled-result limits; the fraction detected with at least five minutes of lead includes all eligible events in its denominator. Confidence intervals resample audited independent groups and all their linked patients/records together, never independent overlapping windows. A degenerate all-correct bootstrap interval does not bound unobserved failures; small test cohorts and all synthetic metrics remain insufficient evidence of clinical usefulness.

Latency reports median and 95th percentile wall time for `Predictor.predict`, including evidence calculation, with hardware/Python metadata. A separate offline replay latency includes ECG I/O, feature extraction, label generation and selected prediction/evidence, while excluding comparison inference and bootstrap. Neither timing is an online-device benchmark; both scopes are explicit. Runtime and evaluation use the same persistence, hysteresis and cooldown implementation. SHDB-AF's upstream zero-phase filtering remains a streaming limitation even with causal feature code.


## Feature measurement contract

`causal-rr-v2` preserves the trailing-history target and quality limits. The causal bandpass detector uses the 99th percentile of energy rather than the global maximum, preventing an isolated large peak from suppressing ordinary beats across the history. Cross-lead matching is symmetric, one-to-one within 80 ms. This is an engineering quality heuristic, not validated bSQI. Primary-lead missing samples invalidate any RR interval spanning them. Adjacent-pair statistics and entropy never bridge invalid intervals.

The 17 new inputs are RR median/IQR/MAD/CV; Poincare SD1/SD2 and lag-one RR correlation; SampEn; HR, RR CV and RMSSD over trailing 60/300 seconds; and their 60-minus-300-second differences. These are descriptive RR measurements, not certified normal-to-normal HRV. Short-window measures require at least ten valid intervals and 80% plausibility. SampEn uses m=2, tolerance=0.2 population standard deviation, at least 50 contiguous valid RR, and the last 256 at most; no-match estimates remain missing. The minimum and cap are engineering choices. Exact pairwise comparisons are bounded O(n²).

Baseline means and population variances update only after constructing the current prediction row from quality-accepted windows. Each field tracks its own count. After the configured cap, updates become exponential with alpha=1/cap. Zscores require at least five previous field updates and variance greater than 1e-12 in squared field units; they describe standardized deviation, not clinical confidence. Source SHDB zero-phase preprocessing remains a separate streaming limitation.
